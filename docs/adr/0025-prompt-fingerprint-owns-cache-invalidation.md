# ADR-0025: 快取失效由 prompt 指紋負責，不保留人工清除介面

Date: 2026-08-29 | Status: accepted

## Context

設定頁的「AI 回答庫」分頁列出所有查過的字、可搜尋、可看內容、可單筆清除。
它在 1.6.0 加入時的用途寫在設定頁的說明裡：「已快取的回答不會自動重查；測試新服務時可到
『AI 回答庫』清除。」

1.7.0 為了讓改 prompt 或換模型後不吃到舊答案，加入了 `lookupVariant()` 與 `explainVariant()`：
把 model、profile、`SYSTEM_RULES` 與使用者 template 一起 `JSON.stringify` 成 `variant` 存進快取列，
命中條件要求 `row.variant === variant`。換模型或改 prompt 之後，指紋不同，整批快取自動失效重查。

也就是說，那一頁被寫下來的唯一用途，已經由程式自己處理掉。設定頁那句說明從那時起就是錯的，
但沒有人回頭改，於是一個沒有理由存在的分頁靠著一段過時的說明繼續留在導覽列上。

## Decision

- 快取失效的責任完全屬於 `variant` 指紋。任何影響 AI 輸出的輸入改變，都要進指紋，
  不靠使用者手動清除。
- 移除「AI 回答庫」分頁與 `CachedAnswers.vue`，以及只服務這一頁的 `listCachedWords` message。
- 保留 `deleteCachedWord`，改由「我的攔路虎」展開後的「重查」使用：
  先對該列打 tombstone，再走一次 `lookup`。`putCached` 以 `word` 主鍵整列覆蓋，
  `deletedAt` 會被寫回 `null`，同步端看得到這次更新。
- 設定頁那句說明改寫成事實：換模型或改 prompt 會自動重查。

## Alternatives

- **只改分頁名稱**：原本的打算。但名字取得再好，也還是一個沒有用途的分頁。
- **保留分頁，只修正說明文字**：說明會變成「這裡沒什麼事可做」，那就不該有這個分頁。
- **保留瀏覽功能，拿掉清除功能**：唯一剩下的內容是「查過但從沒收藏」的字，
  也就是瞄一眼就走掉的字，對學習沒有價值。
- **在設定頁加「清除全部快取」與快取筆數**：目前沒有任何已知情境需要它。
  真的遇到儲存空間問題再加，那時也才知道該顯示什麼數字。

## Consequences

導覽列從五個分頁減成四個。少了一個沒人會點、卻要跟著每次改版一起維護的畫面。

代價講清楚：「查過但從未收藏」的快取列從此沒有 UI 可以看見或清除，
它們會繼續佔用 IndexedDB 與 Supabase 空間。這是接受的取捨，不是遺漏。
需要時再加一個「清除全部」比現在維護一整頁便宜。

真正要守住的規則是：**任何影響 AI 輸出的新輸入，都必須加進 `variant`。**
漏了它就會出現「改了設定卻拿到舊答案」，而且因為已經沒有手動清除的出口，
使用者連繞過去的辦法都沒有。
