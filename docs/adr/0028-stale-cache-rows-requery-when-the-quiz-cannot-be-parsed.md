# ADR-0028: 缺 prompt 指紋的快取列，抽不出題目時重查一次

Date: 2026-09-01 | Status: accepted

## Context

ADR-0025 把快取失效的責任交給 `variant` 指紋，並留下一條規則：任何影響 AI 輸出的輸入都要進指紋。
但指紋是 1.8.1 才加的，而 1.8.1 同時決定「同步下來或舊版留下、缺這些欄位的列視同命中」，
用來避免換一台裝置就整份詞庫重查。

1.8.2 改了 `SYSTEM_RULES.lookup`、要求模型先出一題三選一之後，這條 fail-open 的後果才顯現：
1.8.1 之前查過的字、以及所有同步下來的列都沒有 `variant`，命中判斷把「欄位缺少」當成相符，
所以改 prompt 也不會重查。使用者按 `A` 拿到的永遠是沒有題目的舊 payload，AI 根本沒被呼叫，
整個功能在他的詞庫上形同沒開。

## Decision

三個條件同時成立時視為未命中，重查一次：`guessFirst` 開著、該列沒有 `variant`、
payload 用 `extractQuiz` 抽不出題目。重查後 `putCached` 寫回的列帶著現在的指紋，
所以每個字最多多花一次 AI 呼叫。

## Alternatives

- **拿掉 fail-open，缺欄位一律不命中**：換裝置後整份詞庫按到哪重查到哪，
  直接推翻 1.8.1 那個決定，而且對沒開三選一的人也一樣要付這個代價。
- **只靠卡片右上角的 ↻**：1.8.2 CHANGELOG 原本的說法。要對每一個字手動按一次，
  使用者的實際體驗是「這個功能不能用」。
- **升級時掃全表重查**：一次燒掉整份詞庫的 API 額度，而其中大部分的字使用者不會再看到。
- **把 `guessFirst` 放進 `variant`**：這個開關只管顯示與作答、不改 prompt（1.8.2 明確寫過），
  放進指紋會變成切一次開關就作廢全部快取。

## Consequences

舊詞庫每個字多一次 AI 呼叫，之後回到正常快取行為。已經帶著題目的同步列照樣命中，不浪費。
`guessFirst` 關掉時行為完全等於 1.8.1，這條規則不生效。

已知殘留：`preserveLocalLookupMetadata` 只在 payload 相同時保留本機欄位，
所以被遠端改寫過的列會掉指紋、再重查一次。這是接受的代價，不是遺漏。

ADR-0025 那條規則要補上後半句：**指紋只能保護加入指紋之後產生的列。**
改變輸出格式時，還要問「更早的列拿什麼判斷該不該失效」，
而答案不能是「使用者自己手動處理」。
