# ADR-0004: 查詞從批次 JSON 改成單字 Markdown

Date: 2026-08-24 | Status: accepted

## Context

使用者反映查詞輸出太簡單,想換成一份完整的詞典式輸出(KK 音標、詞性釋義、
常見搭配、例句、同義反義詞)。問題不在模板寫得好不好,而在他**改不動**:
`SYSTEM_RULES.lookup` 鎖死了「只輸出一個 JSON 物件」「每個釋義不超過 20 個字」,
而系統層不開放編輯,會直接壓過使用者層的模板。

這個鎖是為了批次預取:掃完頁面一次送 30 個字,靠 JSON 把結果拆回各個單字。
要豐富輸出就不能批次,要批次就不能豐富。這是架構層級的取捨,不是改字串能解決的。

## Decision

查詞改成一次一個字、回 Markdown。拿掉掃描後的批次預取,按 A 才發請求。
出處句子一起送進 prompt 做一詞多義消歧。卡片用自寫的極簡渲染器顯示,不做兩層漸進揭露。

## Alternatives

- **保留批次,只放寬系統層規則**:JSON 一放寬就會解析失敗,等於默默廢掉預取,
  還留著一整套處理批次的死程式碼。半套的架構比兩套都糟。
- **兩層查詞(第一層短釋義、第二層完整輸出)**:掃讀速度不變,聽起來兩全其美,
  但要維護兩套 prompt、兩套快取語意、兩種卡片狀態。使用者評估後認為不值得。
- **用 `marked` + `DOMPurify` 渲染**:兩個相依、幾十 KB,而卡片實際只需要
  粗體、標題、清單三種語法。自寫 80 行、零相依、測得到。

## Consequences

**好的**:輸出品質由使用者的模板決定,options 頁真的改得動了。
出處句子進了 prompt,`scale` 在 K8s 文章和音樂文章裡會查到不同的意思。

**壞的**:第一次按 A 要等幾秒(卡片會先顯示「查詢中…」)。失去預取帶來的即時感。

**成本**:每個字一次請求、輸出約 500-800 token,但只有真的按 A 才付錢。
舊的預取是掃完頁面就打 30 個字的請求,絕大多數根本用不到,實際上新做法可能更省。

**快取**:鍵仍然是單字原形,同一個字換一個句子會共用第一次的結果。
這是刻意的取捨,一個字換句就重查太貴,多數情況語意也一樣。

**新的安全邊界**:`src/content/markdown.ts` 是 AI 內容進入 `innerHTML` 的唯一通道,
而卡片會被插進任何網頁。它靠一條不變式擋 XSS:**先跳脫整行,再在已跳脫的字串上
套用行內樣式**。順序反過來就有洞。改那個檔案時必須守住這一點,測試裡有六條專門擋這個。
