# ADR-0030: 三選一補上邊界題當預設題型，選項一律中文

Date: 2026-09-01 | Status: accepted

## Context

`SYSTEM_RULES.lookup` 的兩條出題規則都有前提：語態容易讀錯時問施事者，一般義與技術義
無關時問義項。但規格同時要求「第一、二行固定輸出三選一」。一個字兩條都不成立時
（字義單純、沒有語態陷阱），模型被夾在「一定要出題」和「不放明顯錯誤來湊數」之間，
只能湊。湊出來的題目不用讀句子就選得出來，那一次提取練習等於沒發生，
而且會稀釋 `quizLog` 的答對率。

同一次討論還要決定英英釋義放哪裡，以及三選一的選項要不要跟著改成英文。

## Decision

題型改成依序判斷的三條，第三條是預設：三個選項意思相近，只差範圍、強度或方向。
選項一律用繁體中文。英英釋義只出現在揭曉後的 `## 詞性與釋義`，英文一行、中文一行。

## Alternatives

- **英文定義當選項**：第一版設計。辨別力其實來自干擾項的範圍與方向對比，換成中文一個都沒少；
  英文只在使用者剛承認不認識這個字的那一秒，多收 20 幾個字的閱讀成本。
- **允許不出題（`答案｜0`）**：承認有些字不值得出題。但「先猜再揭曉」的節奏會變得不一致，
  而且真正的問題是規格沒有 fallback，不是題目太多。
- **搭配題或克漏字當預設**：考的是產出能力，需要形近字或真實搭配才成立。
  對單一義的抽象字一樣湊不出來，沒有解決原本的洞。
- **英英釋義另開 `## 英英釋義` 段**：跟中文釋義內容重疊，而且分開放的話讀者只會看中文那一份。

## Consequences

題型三的干擾項來源和前兩型不同：不是這個字的其他義項，而是意思相近但範圍、強度或方向
不同的定義（`mitigate` 對上 `eliminate`、`aggravate`）。單一義的字因此也出得了題。

代價是題型三最難自動檢查。前兩型有明確的觸發條件，第三型只有「意思相近」這個人工判斷，
模型可能出成偽裝過的送分題。防線一樣落在 `quizLog` 的答對率，不在解析器。

規格裡多了第二個填好的範例。範例是模型真正會抄的東西（ADR-0029），所以 `prompt.test.ts`
現在把兩組範例抓出來餵回 `extractQuiz`，並斷言選項不含英文字母。
