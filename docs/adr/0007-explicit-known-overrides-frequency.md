# ADR-0007: 用 known 狀態覆蓋詞頻判定

Date: 2026-08-25 | Status: accepted

## Context

通用詞頻排名無法反映個人的專業背景。DevOps 文件裡的 `timestamp`、`query`、`restart`、
`API` 等字可能排名較後，卻早已是使用者熟悉的工作詞彙。只提高全域門檻會同時漏掉其他真正的生詞。

## Decision

詞頻只當預設判定，`words.status` 保存人工例外：`unknown` 永遠高亮，`known` 永遠不高亮。
使用者指向單字按 `X` 可切換 `known` 與自動詞頻判定，不必先呼叫 AI；按 `Space` 維持生詞收藏語意。

## Alternatives

- **提高全域詞頻門檻**：會一次排除大量仍不熟悉的字，粒度太粗。
- **另建熟詞表**：會和既有 `words` 表重複保存單字、時間與刪除狀態。
- **查詞後才允許排除**：多一次操作，也會為已認得的字產生不必要的 API 費用。

## Consequences

高亮會逐步貼近個人專業詞彙，而資料量只跟實際標記過的字成長。
同一個 `X` 再按一次會移除人工例外，恢復由目前門檻判定。
