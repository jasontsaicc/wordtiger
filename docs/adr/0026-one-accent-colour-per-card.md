# ADR-0026: 卡片只用一個重點色，區塊分成參考與帶走兩層

Date: 2026-08-29 | Status: accepted

## Context

頁面卡片的樣式是逐次疊加出來的：先有查詞卡的 `## 標題`，再加句子教練的
`意思｜拆法｜卡點｜帶走｜用法｜例句` 區塊，每次都挑一個「看起來合理」的顏色。
累積下來，同一張卡上有四組互不相干的色系：靛藍標題 `#4f46e5`、紫色「帶走」`#f5f3ff`／`#ddd6fe`、
橘色「卡點」`#fff7ed`、灰底「拆法」`#f8fafc`，頂部還有琥珀／玫瑰／青三色的彩虹漸層。

問題不是某一個顏色選錯，而是沒有「哪個顏色代表什麼」的規則。
沒有規則就沒有停下來的地方，下一個區塊還是會再挑一個新顏色。

深色模式的維護面積也跟著長：`prefers-color-scheme: dark` 底下要逐條覆蓋十幾個選擇器，
每加一條規則就多一個會漏改的地方。`.error .body` 就是漏掉的那一個，
`#b91c1c` 壓在深色底上長期讀不到。

## Decision

- 一張卡只有一個重點色：琥珀 `#f59e0b`（文字用 `#b45309`，深色用 `#fbbf24`），
  其餘一律石板灰階。語意色只保留錯誤紅，且淺深各一個值。
- 區塊分兩層，這是規則，不是配色偏好：
  - **參考層**（原文、拆法、白話英文、用法、例句）：無底色，左側 2px 灰線。
  - **帶走層**（卡點、帶走）：琥珀左線 + `#fffbeb` 淺底。要你帶走的才點亮。
- 查詞卡的 `## 標題` 與拆句卡的區塊套同一套視覺，兩張卡讀起來是同一個東西。
- 樣式改由 `.card` 上的 CSS 自訂屬性驅動，深色模式只換 token，不重寫選擇器。
- 頂部漸層改成單一琥珀色相，但保留 `background-size: 200% 100%`，
  載入中的 `stripe` 動畫才還跑得動。

## Alternatives

- **全灰階，只有「意思」有顏色**：最安靜，但長回答往下捲時區塊層次會塌掉，
  而「帶走」正是最該被看見的一段。
- **卡片固定深色，不跟網頁主題走**：只剩一套顏色，維護面積最小，白底文章上對比也最強。
  但深色網站上兩塊深色會疊在一起，而且跟 options 頁的淺色調不是同一個家族。
- **每個區塊各自一個語意色**：資訊量看似最高，實際上就是現況。
  六個區塊六個顏色等於沒有顏色。
- **沿用現況只調飽和度**：不解決缺少規則的問題，下次還是會再多一個色系。

## Consequences

深色模式從十幾條覆蓋規則減成一組 token。`.error .body` 在深色下改用 `#fca5a5`，
順手修掉一個長期讀不到的錯誤訊息。

`prefers-reduced-transparency` 與 `prefers-color-scheme: dark` 同時成立時，
兩個媒體查詢會爭 `--surface`。深色區塊裡巢狀再寫一次 reduced-transparency 覆蓋，
順序才不會讓不透明背景被半透明的值蓋回去。

**已知未收的債**：同一份 `renderMarkdown` 輸出在 options 頁還是另外兩個顏色。
`ReviewSession.vue` 的 `.answer :deep(.h)` 是 `#4f46e5`，
`WordLibrary.vue` 的 `.dictionary :deep(.h)` 是 `#6557c5`。
於是同一段 AI 回答在三個地方有三種標題色，而且那兩個紫色彼此也不一樣。

收這筆債的規則是：**AI 回答的內容一律用琥珀，options 頁自己的介面（篩選按鈕、同步按鈕）
維持紫色**，讓「這是 AI 講的話」在整個擴充功能裡是同一個視覺訊號。
這次刻意不做，因為當時要交付一包待驗收的建置，不適合夾帶沒被看過的視覺改動。
