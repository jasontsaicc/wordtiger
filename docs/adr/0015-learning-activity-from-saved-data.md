# ADR-0015: 學習足跡只由收藏資料推導

Date: 2026-08-26 | Status: accepted（部分被取代）

> 2026-08-27：「新收藏」改依 `collectedAt` 而非 `words.createdAt`，見 ADR-0019；
> 複習成績改用事件表，見 ADR-0020。本文其餘決策仍然有效：
> 不記錄一般瀏覽、不申請 tabs／history 權限、月曆只呈現使用者實際保存過的內容。

## Context

使用者希望用月曆看某天新增哪些詞、讀過哪些文章。若直接記錄每個開啟的分頁，可以得到完整瀏覽史，
但需要更廣的 tabs／history 權限，也會把「學習回顧」變成不必要的監控資料。

現有 `words.createdAt` 已代表首次收藏時間；`contexts.createdAt`、`url`、`title` 已代表使用者確實從某頁
保存過學習材料，足以回答產品真正需要的問題。

## Decision

- 月曆完全由仍存在的 `words` 與 `contexts` 即時計算，不新增 activity 表、事件紀錄或權限。
- 「新收藏」依 `words.createdAt`；「來源文章」只計算當天至少保存一條 context 的 URL，同頁多詞合併。
- 日期依使用者目前的本地時區呈現；月份切換、每日詞彙與來源連結都在 options 本機計算。
- 不記錄沒有收藏內容的一般瀏覽頁，也不把衍生活動資料同步到 Supabase。

## Alternatives

- **監聽所有分頁與瀏覽歷史**：資料完整，但權限、隱私與商店審查成本遠高於學習收益。
- **新增 activity event 表**：能保留刪除前歷史，但會複製既有 timestamp、增加同步與 tombstone 邏輯。
- **只顯示總數、不做月曆**：最簡單，但無法回答使用者最在意的「哪一天學了什麼」。

## Consequences

學習足跡不是瀏覽紀錄或不可變稽核日誌：刪除收藏後，相應活動也會消失；沒有收藏的文章不會出現。
這個不完整是刻意的隱私邊界。好處是不增加資料收集、資料表、同步流量或網站權限，舊資料也能立刻呈現。
