# ADR-0013: 「帶走」片語只服務教學，不作為高亮比對 key

Date: 2026-08-26 | Status: accepted

## Context

`D` 回覆的「帶走」片語目前直接沿用 `words` 詞庫，而下一步規劃是片語自動高亮，
最自然的做法就是拿詞庫裡的片語去掃網頁。2026-08-26 用真實 API 對四個模型實測後，
這個假設不成立：同一句、同一個 prompt，`gpt-5.6-luna` 回
`keep A pending until B becomes available`，`gpt-4o-mini` 回整個子句照抄。
前者的 `A`、`B` 是佔位符，永遠比對不到網頁文字；後者只會在原本那一頁命中一次。

## Decision

「帶走」定位為教學用的可套用句型，不作為高亮比對的 key。
它仍可進入 `words`／`contexts` 做語境複習，並以既有 `lookup_cache` 保存片語 AI 詞典；
「可收藏、可複習」不代表「適合逐字掃描網頁」。
片語自動高亮要另外設計來源，不沿用這個欄位。

## Alternatives

- **直接拿「帶走」當高亮 key**：不用改任何東西，但實測顯示兩種主要輸出形態都比對不到，
  功能會看起來壞掉，而且原因藏在模型輸出裡很難查。
- **改 prompt 只產可比對的字面片語**：能解決比對，但會犧牲句型教學，
  而那正是 `D` 跟一般查詞工具的差別。
- **同時產兩個欄位**：一次請求拿教學句型與比對片語，但會拉長回應、增加解析面，
  而且高亮功能還沒證明值得做，先付這個成本太早。

## Consequences

片語自動高亮的成本比原先估計高，要先定義「什麼是可比對的有價值片語」再動手，因此往後排。
好處是這個問題在寫掃描器之前就被發現，而不是寫完之後才發現比對不到。

`extractTakeaway()` 因此擋掉三種不可用的輸入：含 `…` 或 `...` 的截斷片語（Luna 兩次實測都截斷，
加了 prompt 規則後才修正，但解析器仍不依賴模型行為）、英文夾中文的佔位句型如 `provided [條件]`、
以及模型多印一次「帶走｜」前綴時會誤取到的中文段。三個守衛都用四個模型的實測輸出驗過。

副作用是部分教學上有用的句型不會進詞庫。這是刻意的取捨：寧可少收，
也不要在跨裝置同步的詞庫裡留下永遠比對不到、又沒人知道為什麼在那裡的死 key。
