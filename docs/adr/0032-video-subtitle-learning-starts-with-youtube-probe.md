# ADR-0032: 影片字幕學習先驗證 YouTube，再決定 Netflix 與沉浸式翻譯支援

Date: 2026-09-05 | Status: accepted

## Context

攔詞虎已有文章中的 `A`、`S`、`D`、收藏語境與 FSRS 複習。使用者希望把同一套流程帶到
YouTube、Netflix 與沉浸式翻譯的雙語字幕。現有功能可重用，但字幕是高頻變動內容，
字幕來源、斷句、全螢幕和播放器快捷鍵都跟文章不同。

沉浸式翻譯公開說明支援 YouTube 和 Netflix 雙語字幕，但目前沒有可依賴的公開字幕讀取 API。
因此不能把另一個擴充功能的 DOM 結構當成穩定契約。

## Decision

2026-09-05 決定先優化 YouTube，不處理 Netflix 或沉浸式翻譯專屬整合；待 YouTube
試點完成並實測後，再決定是否另開 Netflix ADR。

最小實作範圍限定為：讀取 YouTube native caption DOM；按 `A`、`S`、`D` 固定當下字幕並
暫停影片；收藏時沿用既有 DB，保存帶 `t` 的來源 URL、標題、英文字幕與可讀播放時間；
隔離卡片快捷鍵與播放器快捷鍵；全螢幕時將卡片 mount 到 fullscreen element。既有 AI、卡片、
語境與 FSRS 流程重用，不承諾精準逐句循環播放。

目前只有 jsdom 測試；真實字幕 DOM、播放器快捷鍵、fullscreen 顯示與時間戳回跳仍需瀏覽器
手動實測。字幕抓不到時的原因提示、手動選字或貼上句子備援尚未列入本次實作，留待後續驗證與改善。

## Alternatives

- **同時做 YouTube、Netflix、沉浸式翻譯**：表面上一次完成，實際上會把三套不穩定 DOM 與
  播放器行為綁在同一個版本，定位失效原因困難。
- **直接讀 `video.textTracks`**：這是標準 API，但不能保證平台把畫面字幕放入該介面；只可作探查
  的其中一條來源，不能當唯一方案。
- **先做逐句循環、聽寫、整片匯出**：都依賴準確字幕時間軸，超出第一版「查詞與收藏」的必要範圍。

## Consequences

影片功能先限制在一個平台和一條學習閉環，程式仍可重用現有 AI、卡片、語境與複習資料。
若 YouTube 試點證明需要網站專用選擇器或播放控制，這些細節應放在可替換的 adapter，
而不是散進既有文章高亮流程。Netflix 與沉浸式翻譯是否支援，取決於實測結果另開 ADR。
