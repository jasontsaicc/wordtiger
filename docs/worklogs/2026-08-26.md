## 真實 API 驗證

用 repo 裡的 `lookupWord` 與 `explainSentence`，對 `gpt-4o-mini`、`gpt-4.1-nano`、
`gpt-5-mini`、`gpt-5.6-luna` 各跑 A／S／D 三個功能。

抓到三個問題，都是單元測試 mock 掉 AI 之後永遠測不到的：

1. **`reasoning_effort` 特例太窄。** 原本只對 `gpt-5.6-*` 關推理，`gpt-5-mini` 沒關，
   查詞要 28 秒。實測 `gpt-5-mini` 不接受 `'none'`（回 400 Unsupported value），
   只接受 `'minimal'`。改成分兩段對應後，28.1 秒降到 4.0 秒。
2. **`extractTakeaway` 硬取第二段。** 模型偶爾多印一次「帶走｜」前綴，
   `gpt-4.1-nano` 與 `gpt-5-mini` 各出現一次。改成掃描第一個純英文區段。
3. **Luna 會截斷帶走片語。** 兩次都輸出 `can be retried without changing…`。
   在 `SYSTEM_RULES.grammar` 加一條禁止省略的規則後，三次全部完整。
   解析器同時擋掉含 `…`／`...` 與英文夾中文的片語，不依賴模型行為。

四項新測試直接用實測輸出當 fixture。

Luna 切成四個完整意義區塊，`gpt-4o-mini` 切成九塊逐詞切。
`gpt-4.1-nano` 最省但帶走片語常失敗。既有使用者的設定不受影響，只有新安裝拿到新預設。

## 對片語自動高亮的發現

同一句、同一個 prompt，Luna 給 `keep A pending until B becomes available`，
`gpt-4o-mini` 給整個子句照抄。學習用途 Luna 明顯較好，但兩者都不能當高亮比對的 key：
Luna 的 `A`、`B` 是佔位符永遠比對不到文字，`gpt-4o-mini` 的長句只在原頁命中一次。

「帶走」是為教學優化的欄位，不是為比對優化。片語自動高亮需要另一條 prompt 或另一個欄位，
不能沿用。新增 [ADR-0013](../adr/0013-takeaway-is-not-a-highlight-key.md)。
